# Contributing Sony lens corrections to LightCraft

Researched 2026-10-09 using the upstream GitHub API and first-party repository documents. Pull-request status is a snapshot, not a promise that it will remain unchanged.

## Official contribution process

- LightCraft is MIT OR Apache-2.0, and its README directs both humans and agents to read `AGENTS.md`. The repository's recursive `main` tree had no `CONTRIBUTING.md` or pull-request template; the contribution guidance is in the README, AGENTS, and linked standards. Questions and proposals can be discussed on ArtCraft Discord; discussion first is invited, not stated as mandatory. [README](https://github.com/storytold/lightcraft#contributing), [repository tree](https://github.com/storytold/lightcraft/tree/main)
- Implementation must be clean-room and pure Rust: public specifications and independent black-box observations are suitable evidence. Do not read Adobe binaries or GPL photo/raw implementations, copy Adobe assets/profiles, or add C/C++ product dependencies. Existing crate layering and normalized coordinates must be respected. [AGENTS](https://github.com/storytold/lightcraft/blob/main/AGENTS.md#non-negotiables)
- The official gate is green `cargo xtask ci` before every commit, with one task ID per commit and the environment's attribution trailer. It covers formatting, Clippy with warnings denied, tests, layers, asset checks, and WASM. New features need at least one test that fails without the change; input-derived offsets/counts require checked access and arithmetic, bounded allocation, and errors rather than panics. [AGENTS](https://github.com/storytold/lightcraft/blob/main/AGENTS.md#never-crash-outranks-feature-work), [testing](https://github.com/storytold/lightcraft/blob/main/AGENTS.md#testing--performance-do-this-often)
- When a feature lands, update its `docs/parity.md` row and top-gap list in the same commit; update the ROADMAP assessment when a listed gap closes. The applicable task is `LR-EDIT-OPTICS-PROFILE`, currently partial. Do not mark all Sony correction support complete because distortion on one body works. [AGENTS startup requirements](https://github.com/storytold/lightcraft/blob/main/AGENTS.md#start-every-session-here), [parity tracker](https://github.com/storytold/lightcraft/blob/main/docs/parity.md)
- Validate user-visible changes through the app's control channel/headless snapshots, inspect the rendered result, and check performance. Private photos stay local; media must not be committed. Test corpus downloads are CC0 and stored in gitignored `corpus/`, with source/checksum records. [AGENTS](https://github.com/storytold/lightcraft/blob/main/AGENTS.md#running-and-looking-at-the-app)
- Contributor credit defaults to `@username`. At PR preparation, if the human has no entry in `contributors/people.toml`, the instructions ask agents to offer real name, display name, or public-profile-name synchronization once. Add only the human's own explicitly chosen entry; never edit generated `contributors.json`. [credit instructions](https://github.com/storytold/lightcraft/blob/main/AGENTS.md#contributor-credits-about-window), [credit documentation](https://github.com/storytold/lightcraft/blob/main/docs/contributors.md)

## What is already solved, and what remains

| Item | Status on research date | Relevance |
|---|---|---|
| [PR #498](https://github.com/storytold/lightcraft/pull/498) | Open, unmerged | Reads Sony raw-IFD signed 16-sample `0x7037` distortion tables into existing `WarpRectilinear`, explicitly limited to exact `ILCE-7RM4A`, Bayer, native 3:2. Independently checked with FE 24–105 and FE 200–600. Does not implement vignetting, lateral CA, other table lengths, or other models. |
| [PR #571](https://github.com/storytold/lightcraft/pull/571) | Open, unmerged | Reload from Disk refreshes catalogued lens data, enables corrections for untouched photos, preserves edited settings. Addresses photos imported before RW2 support; it does not implement Sony table decoding. Potentially useful alongside a future Sony decoder for already-imported photos. |
| [Issue #329](https://github.com/storytold/lightcraft/issues/329) | Open | Broader lens-profile database/calibration request. Embedded per-image correction and independently measured profiles are the accepted direction. |
| [PR #262](https://github.com/storytold/lightcraft/pull/262) | Closed | Panasonic/Leica embedded distortion precedent. Main's parity tracker lists DNG and RW2/RWL corrections, but Sony correction tables remain unread. |

The strongest relevant review is the maintainer's response to #498: an early implementation automatically warped every Sony Bayer ARW with a 16-entry table at 3:2, but an A7 III corpus sample gained about 2.5% corner warp without independent validation. The maintainer required checks against independent references on other bodies, or restriction to validated models. The author chose exact `ILCE-7RM4A` restriction. Matching a tag or table length alone is insufficient evidence that the mapping, scaling, or crop interpretation transfers. [Maintainer review](https://github.com/storytold/lightcraft/pull/498#issuecomment-6084452062), [author response](https://github.com/storytold/lightcraft/pull/498#issuecomment-6085115027)

The #498 branch documentation explicitly excludes different table lengths. Its corpus also contains 11-sample tables on A7 IV 14-bit and RX100 III files, but those are exclusion checks, not validated geometry. An α6700 11-knot implementation therefore cannot be justified by borrowing the A7R IVA formula or simply adding its model name. Compare independent corrected/uncorrected references across lenses, focal lengths, edge/corner coverage, crop/aspect and compression variants, and report geometric residuals. Table-fit error only measures approximation of our assumed mapping. [Branch validation and coverage document](https://github.com/QuirkyTurtle94/lightcraft/blob/sony-embedded-lens-corrections/docs/sony-lens-corrections.md)

Repository issue/PR title-and-body searches for `sony`, `distortion`, `a6700`, and `6700` found no existing α6700 lens-correction fix. `6700` matched older camera-colour proposals #113 and #115, not a lens decoder. This is a scoped search result, not proof that no unindexed branch, comment, or unpublished solution exists. [Sony search](https://github.com/storytold/lightcraft/issues?q=sony), [α6700 search](https://github.com/storytold/lightcraft/issues?q=6700), [distortion PR search](https://github.com/storytold/lightcraft/pulls?q=is%3Apr+distortion)

Lensfun is not an acceptable shortcut for this project. A maintainer explicitly rejected its copied database in #279 and welcomed separate work based on original measurements or embedded camera corrections. [Maintainer decision](https://github.com/storytold/lightcraft/pull/279#issuecomment-6066550379)

## Suggested contribution scope

Build a narrowly validated α6700 embedded-distortion contribution that reuses LightCraft's existing lens model and records the independent geometry evidence. Relate it to #498 and #329, distinguish it from #571's catalog refresh, and avoid claiming CA/vignetting or broad Sony support without separate evidence. Review upstream again before opening a PR because these branches are active. This recommendation follows the explicit #498 review boundary rather than inferring correctness from metadata detection.

No external comments/messages were posted, no prohibited decoder source or Adobe asset was consulted, and this research did not modify implementation code.

Local status at research time: the earlier α6700 prototype was uncommitted and uninstalled, with a targeted synthetic test passing. The fork extension builds on PR #498; independent geometry validation remains outstanding. See `docs/sony-lens-corrections.md` for the extension’s limits. No new PR has been created. This local status is not evidence of an upstream solution or readiness to merge.
